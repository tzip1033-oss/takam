## 2. ארכיטקטורה

```
data/raw/*.docx  ->  ingest (קטעים לפי סעיף + מטא-דאטה)  ->  אינדקס (BM25 + embeddings)
שאלה -> סינון תוקף (קוד) -> שליפה -> סף סירוב (קוד) -> LLM (רק מהקטעים) -> תשובה + ציטוט + "פתח מקור"
```

## 3. בחירות טכניות מרכזיות

- **חלוקה לפי סעיפים**, לא לפי גודל קבוע; כל קטע נושא מספר הוראה, מהדורה, סעיף וסוג מסמך.
- **מטא-דאטה (מהדורה, תוקף) נלקחת מהאתר** (`data/metadata.csv`) ולא מהקבצים, כי קבצים עלולים להיות מיושנים.
- **חיפוש היברידי** (מילות מפתח + embeddings מקומיים): המסמכים מלאים במספרים ובמונחים רשמיים.
- **סינון תוקף ושיקול סירוב נעשים בקוד**, לא בהנחיה למודל.
- **המודל מוחלף בפונקציה אחת** (`generate_answer`), כדי שאפשר יהיה לעבור למודל מקומי.
- [להשלים: בחירת embeddings, ספק LLM, ערך סף הסירוב]
